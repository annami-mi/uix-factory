# ADR-0005: Стилистика и цветовая схема — две независимые оси

Статус: принято 2026-09-24

## Контекст

До этого решения тема была одной осью: `data-theme="glass" | "light-neutral"`. Требование: **каждое направление (стилистика) должно иметь и светлую, и тёмную схему**. Одна ось смешивала два независимых выбора — характер/материал (стекло или плоский) и светлоту — и вела бы к комбинаторному росту имён (`glass-dark`, `glass-light`, `neutral-light`, …) без явной связи между ними.

## Решение

- **Две оси на `<html>`:**
  - `data-theme` — стилистика: `glass`, `neutral` (материал, форма, характер);
  - `data-scheme` — схема: `light`, `dark`. **Без атрибута схема следует системной настройке** (`prefers-color-scheme`); по умолчанию — light.
- **Источник токенов:** `packages/tokens/source/themes/<стилистика>/<схема>.json`. Каждая стилистика обязана иметь `light.json` и `dark.json` — иначе сборка падает.
- **Сборка** на стилистику генерирует один `dist/<стилистика>.css` с тремя блоками: явный light (+ отсутствие `data-scheme`), явный dark, dark по `@media (prefers-color-scheme: dark)` для отсутствующего `data-scheme`. В каждом блоке — `color-scheme: light|dark` (нативные контролы, скроллбары).
- **Паритет:** все комбинации стилистика × схема определяют один и тот же набор переменных — проверяется тестом сборки. Компонент по-прежнему ссылается только на роли и не знает ни стилистику, ни схему.
- **Списки** `themes` и `schemes` генерируются в `@uix/tokens` — приложения и Storybook их не хардкодят.
- **Storybook:** два переключателя в тулбаре (стилистика, схема + «как в системе»). Матрицы состояний компонентов продублированы для каждой комбинации, чтобы axe проверял контраст во всех.

## Переименования

- `glass` → `glass/dark` (флагман из Figma), `light-neutral` → `neutral/light`.
- Новые, токен-first (ADR-0003): `glass/light`, `neutral/dark`.

## Альтернативы и почему отклонены

- **Плоский список тем** (`glass-dark`, `glass-light`, …) — теряет связь между схемами одной стилистики, приложению нужно знать все имена, «как в системе» пришлось бы писать в каждом приложении.
- **Схема через `@media` без атрибута** — нельзя дать пользователю переключатель и нельзя зафиксировать схему для конкретного продукта.
- **`light-dark()` в CSS** — удобно для отдельных цветов, но наши роли — не только цвета (тени, blur, градиенты фона); двойные значения в каждом токене усложнили бы источник.

## Последствия

- Новая стилистика = папка с двумя файлами; значения тёмной и светлой схем подбираются вместе и проверяются axe в обеих.
- Приложение ставит `data-theme` (обязательно) и `data-scheme` (по желанию, для ручного переключателя).
- Figma (Starter, без modes) по-прежнему содержит только `glass/dark`; остальные схемы — токен-first, см. ADR-0003.
- **Исключение:** стилистика, у которой тёмной схемы пока нет (`bento-contrast`), объявляет `dark.json` псевдонимом светлой (`"uix.scheme-alias": "light"`): набор переменных остаётся одинаковым, сборка выдаёт светлые токены с `color-scheme: light`.
