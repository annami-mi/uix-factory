# UIX Factory

## Цель проекта

Производственная система для быстрой сборки коммерческих веб-продуктов (лендинги → небольшие сайты → магазины → SaaS) одним frontend-разработчиком. Компоненты пишутся один раз; визуальная индивидуальность проекта задаётся набором значений токенов ("стилистикой"), а не переписыванием компонентов.

## Стек

- pnpm workspaces (monorepo), без Turborepo/Nx.
- Публичные сайты: Nuxt 4 (SSG/prerender). SaaS (позже): Vue 3 + Vite.
- Стилизация: CSS custom properties + `<style scoped>` + `@layer`. Без Tailwind внутри `packages/ui`.
- Компоненты: свои, поверх Reka UI для сложного поведения (Dialog, Select, Tabs, Tooltip, Menu); простые — на нативном HTML.
- Документация компонентов и стилистик: Storybook (`@storybook/vue3-vite`), переключение через globals/toolbar: стилистика — `data-theme`, схема — `data-scheme` на корне (ADR-0005).
- Тесты: Vitest (логика), `@vue/test-utils` (поведение компонентов), Playwright + `@axe-core/playwright` (e2e, скриншоты, a11y).
- Токены: DTCG JSON → CSS-переменные + TS. Источник значений — Figma (см. `docs/decisions/0003-*.md`), источник истины после переноса — код.

## Архитектурные правила

- Зависимости строго вниз: `sections → patterns → components → foundations`. Тема влияет только на значения токенов.
- Каждая стилистика — в двух схемах, светлой и тёмной (`themes/<стилистика>/{light,dark}.json`, ADR-0005); без `data-scheme` схема следует системе.
- Компонент не знает, какая активна стилистика — только ссылается на семантическую роль токена с безопасным fallback.
- Новый компонент/паттерн/секция появляется только из реального экрана — не "потому что есть в популярных дизайн-системах".
- Абстракция — не раньше второго реального применения (кроме foundations/tokens/ui, которые переиспользуются с первого дня).
- **Mobile-first everywhere**: компонент проектируется и тестируется сначала на 360–390px; десктоп — расширение. Дефолтные размеры интерактивных элементов — комфортные для тача, компактные — не дефолт. CSS mobile-first (`min-width`), container queries для компонентов/секций, media queries только в page shell. Storybook viewport по умолчанию — мобильный.

## Naming

- Токены: `color/<role>/<state>`, `space/*`, `size/*`, `radius/*`, `type/<role>/<size>` (не `label/md`/`body/md` без общего префикса), `surface/<role>/<state>` для материала поверхности (bg/border/shadow/backdrop).
- Токен без понятной роли (пример из аудита — `White: #FAFAFA`) не переносится в код без переименования в Figma.

## Правила компонентов

- Не дублировать props ради паритета со сторонней библиотекой — обёртка оправдана только если закрепляет повторяемое поведение или семантический API.
- Не смешивать бизнес-логику, структуру компонента и визуальную тему.
- Не использовать необъяснимые magic numbers — только токены.
- Не создавать новый компонент под каждую композицию — контракт контента один, композиционно разные варианты (напр. три Hero) — отдельные компоненты с общим типом контента.

## Требования к проверке

- Desktop и mobile — обязательно на каждом этапе, начиная с mobile.
- Состояния loading/empty/error/disabled/focus — где применимы.
- axe без serious/critical, keyboard-сценарий, `prefers-reduced-motion`.
- Смена стилистики (`data-theme`) и схемы (`data-scheme`) не должна требовать правок компонента — это явный критерий приёмки, не факультатив. Контраст (axe) проверяется во всех комбинациях.
